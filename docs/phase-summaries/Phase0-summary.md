## What Was Built

### Backend

| Item | Description |
|------|-------------|
| `BaseEntity` | Abstract base with UUID v7 ID + audit fields (`CreatedAt`, `UpdatedAt`, `CreatedBy/UpdatedByUserId`) |
| `ITenantOwned` / `ISoftDeletable` | Interfaces enforcing multi-tenant and soft-delete contracts on all entities |
| `Tenant` | Top-level tenant entity (one row per company) |
| `User` | Tenant-scoped user with `UserRole` enum (Admin / Operator / Measurer) |
| `RefreshToken` | Hashed refresh token with expiry + revocation timestamp |
| `AppDbContext` | EF Core DbContext with global query filters for tenant isolation and soft delete |
| `InitialIdentity` migration | Creates `tenants`, `users`, `refresh_tokens` tables in PostgreSQL |
| `AuditInterceptor` | `SaveChangesInterceptor` that auto-fills audit timestamps, sets `TenantId`, and converts hard deletes to soft deletes |
| `AuthService` | Login, refresh, logout — issues JWT access tokens + hashed refresh tokens |
| `JwtService` | Generates and hashes JWTs (HS256, 15-min access / 7-day refresh) |
| `PasswordHasher` | PBKDF2-SHA256 with 100k iterations, salt+hash stored as `salt.hash` |
| `CurrentUserAccessor` | Reads `sub`, `tenantId`, `role` from JWT claims (short names, `MapInboundClaims = false`) |
| `POST /api/v1/auth/login` | Email + password → access + refresh tokens |
| `POST /api/v1/auth/refresh` | Valid refresh token → new token pair (old revoked) |
| `POST /api/v1/auth/logout` | Revokes refresh token server-side |
| `GET /health` | JSON health check (`{"status":"Healthy","timestamp":"..."}`) |
| Swagger UI | JWT Bearer auth support via Authorize button; API title + version |
| Serilog | Console + rolling file (`logs/shisha-.log`) + Seq (`localhost:5341`) with request logging |
| `ApiFactory` | `WebApplicationFactory<Program>` + Testcontainers PostgreSQL; graceful fallback when Docker unavailable |

## Architecture Decisions

| Decision | Reasoning |
|----------|-----------|
| `IgnoreQueryFilters()` in `AuthService.LoginAsync` and `RefreshAsync` | Login/refresh have no tenant context yet; global tenant filter would return zero results. Documented exception to the "no IgnoreQueryFilters" rule. |
| JWT short claim names (`"sub"`, `"role"`) | `MapInboundClaims = false` on JwtBearer means claims are NOT mapped to .NET long-form names. `CurrentUserAccessor` reads `"sub"` and `"role"` directly. |
| Access token in memory + refresh token in `localStorage` | Balances security (XSS can't steal short-lived token) with persistence (session survives page reload). |
| `auth:logout` custom window event | Decouples the Axios interceptor (infrastructure) from `AuthContext` (React) — interceptor fires the event on irrecoverable 401, context listens and clears state. |
| Dark mode via `.dark` class on `<html>` + `localStorage` | Tailwind's `darkMode: ['class']` strategy; anti-flash init script in `index.html` ensures correct theme before first render. |
| Testcontainers with `IsAvailable` guard | Integration tests gracefully no-op when Docker is not running (e.g. in CI without Docker), so `dotnet test` stays green. |

## Next Phase Overview

Phase 1 builds the **Designer** — the core feature that prompted building this app. A measurer at a client's apartment enters the opening width and height; the app computes glass panel widths using the formulas in `DesignerLogic.md`, renders an interactive SVG drawing, and generates a PDF for the glass factory. This phase depends on Phase 0's foundation: the auth + layout shell is the container the Designer page lives in, the JWT interceptor handles API calls, and the type generation script will produce typed hooks for the new measurement endpoints.
